## 1. 规划原则（含 7 项评审原则落地）

1. **分阶段**：Phase 0 准备 → Phase 1 MVP（Must 闭环）→ Phase 2 增强（Should）→ Phase 3 智能与扩展（Could + 性能多副本）。
2. **全生命周期**：每阶段含 需求确认 / 设计确认 / 开发（前端+后端）/ 测试（单元+集成）/ 部署运行 / 上线。
3. **最小化与可施工**：功能模块拆到 **接口 / 页面 / 定时任务 / 跑批 / 核心算法** 粒度，单任务 **0.5~3 人天**，过大任务已拆子任务（ID 后缀 a/b/c…）。
4. **依赖与并行**：标注依赖任务与可并行关系；关键路径优先；无依赖任务并行开发。
5. **可追溯**：每个任务标注 **需求 ID（FR-xx / DC-xxx）** 与 **详设章节（§x.y）**，可回溯需求与详设，杜绝范围蔓延。
6. **可独立交付**：接口/算法以 mock/契约桩独立单测；前端按 §2.21 契约并行。
7. **优先级**：每任务标 **优先级 P0（主干必须）/ P1（重要）/ P2（增强可延后）**，与时间紧时的主干保障对应（与阶段编号 P0~P3 区分）。

## 3. 依赖关系与并行开发分析

### 3.1 关键路径（Critical Path，父子依赖见任务 ID 后缀）
```
P0-04 数据模型 ─┬─ P1-01a/b/c 采集 ─ P1-05 夜算 ─┐
                └─ P1-03a/b/c/d 评估算法 ─ P1-04a/b 评估接口 ┤
P0-03 工程基建 ─────────────────────────────────┤
P1-02a/b 数据中心 ─ P1-06a/b/c 筛选 ─┐            │
P1-07a/b 模拟交易 ─ P1-08a/b/c 组合 ─┤            │
P1-09a/b 实验室 ───────────────────┤            ├─ P1-12 仪表盘 ─ P1-19a/b 首页 ─ P1-21 集成 ─ P1-23 上线
P1-10a/b/c 调度 ───────────────────┘            │
P1-13~P1-19 各页面（并行，契约稳定后）────────────┘
```
**结论**：最长为 `P0-04 → P1-03a/b/c/d → P1-04a/b → P1-12 → P1-19a/b → P1-21 → P1-23`，约 8 周；评估算法（P1-03*）与采集（P1-01*）是 MVP 两大支点，须优先启动。

### 3.2 可并行组（拆分后并行度提升）
- **后端并行**：`P1-01a`(采集) 与 `P1-03a`(指标) 在 `P0-04` 后**立即并行**（算法可用 mock NAV 先行）；`P1-02* / P1-07* / P1-09*` 在各自数据/算法就绪后并行。
- **前后端并行（契约优先）**：接口契约见 §2.21；前端页（`P1-13*~P1-19*`）在对应接口"契约冻结"后可并行开发，不阻塞。
- **测试并行**：`P1-20a/b/c` 单测随算法/接口完成持续进行；`P1-21` 集成在链路打通后。
- **Phase 2/3 内模块互不依赖**：`P2-01*/P2-03*/P2-05*` 与 `P3-01*/P3-03*` 各自独立，可多任务并行。

### 3.3 强依赖（不可并行）
- 所有接口任务依赖 **P0-04 数据模型**；`P1-04*` 依赖 `P1-03*`；`P1-12` 依赖 `P1-02*~P1-11`；`P1-19*` 依赖 `P1-12`；部署/上线依赖对应测试通过。

## 5. 各阶段验收要点（出口标准）

- **Phase 0**：`compose up` 起全服务；CI 绿；DB migrate 成功；admin 登录 + 错误码 + 统一响应体可用。
- **Phase 1 MVP**：采集跑通且质量看板有数；单基评估/归因/PEG·ERP 与 §3.3.8/§3.3.7 一致；NL 解析准确率 ≥0.85；模拟交易用真实收盘净值、重置二次确认；评分全站一致（ADR-002）；MVP 一键部署上线、监控/备份生效。
- **Phase 2**：风险测评联动默认配置与模拟起点；估值定投信号 PE 分位→倍数正确；宏观卡+外围传导+股债中枢；学习词典/路径/案例沙盒/行为问卷可用。
- **Phase 3**：持仓穿透舆情带 source/published_at；AI 问答拒答无依据、周报自动生成；多 collector 副本并行且墙钟≈单副本/N；API 多实例 LB + Redis 缓存一致；调度多副本不重复触发；全量上线 + 压测报告。

## 6. 工程节奏与 DoD（Definition of Done，含量化项）

- **迭代节奏**：1 周 1 sprint；周一认领任务、周五演示；Claude Code 按任务 ID 逐条规约。
- **单任务 DoD（量化）**：
  1. 代码实现并通过类型检查与 lint（ruff/black）；
  2. 对应**单元测试通过且覆盖率 ≥ 80%**（测试类任务除外）；
  3. 接口 100% 命中 §2.21 契约与 §4.2 错误码；
  4. PR 合入主干、**至少 1 人（或 AI 评审）通过**；
  5. NL 类任务须过 **160 条评测 ≥0.85** 门禁；
  6. 状态 `未启动`→`进行中`→`已完成`，阻塞项标注 `阻塞`+阻塞任务 ID。
