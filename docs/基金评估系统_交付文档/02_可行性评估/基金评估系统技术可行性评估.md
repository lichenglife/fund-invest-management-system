> **评估对象**：个人学习 + 模拟交易 + 基金评估系统（非实盘、非销售）
> **版本**：**v1.2**（基于 BRD v1.2 + 技术规格 v1.2 + 原型 v1.2，已纳入 grill-me DC-001~012 全部结论）

## 七、技术难点与解决方案（**重新评估 · 按风险重排**）

> v1.2 相对 v1.1 的**真难点**是 A~E 五项（方法学/硬 SLA/工程面），其余为常规项保留。

### 难点 A（**新增·方法学**）：PEG / ERP 在"基金层"的定义
- **问题**：PEG=PE/增速、ERP=股票预期收益−无风险利率，本是**股票/指数级**指标；基金无直接"盈利"，naive 套用会误导。
- **解决**：① PEG/ERP **不在基金层硬算**，改为"以跟踪基准指数/重仓股加权"的近似并明确标注"代理值"；② ERP 用"盈利收益率(EY) − 10Y 国债"近似；③ 阈值着色仅作"相对高低"提示，不作绝对结论。
- **风险**：中（方法学不清晰会比"算不出"更危险，必须先在技术规格定义口径）。

### 难点 B（**新增·算法**）：风格箱"持仓 ∩ 收益回归"交叉验证
- **问题**：主动基金持仓跨市值/风格，单看持仓易漂移；回归法需足够历史与因子收益序列，二者未必一致。
- **解决**：① 因子收益取自中证规模/风格指数历史（AkShare）；② 双方法各给一格，若**分歧>1 格**标注"待人工确认"或取加权；③ 回归窗口≥3 年。
- **风险**：中低（可实现，但需定义"分歧处理规则"，已在技术规格 STYLEBOX_METHOD 预留）。

### 难点 C（**新增·硬 SLA**）：自然语言选基 ≥85% 准确率
- **问题**：歧义句（"稳健一点"）、口语与字段映射（主题/风格taxonomy）是主要失分点；这是唯一带量化达标线的需求。
- **解决**：① 结构化抽取 + 规则兜底（解析失败回退引导文案）；② 构建 **100 条标注评测集**，迭代 prompt 与字段词典；③ 歧义主动反问澄清；④ 安全网=引导式表单永远可用。
- **风险**：中（可达标但需评测投入；即便 85% 未达，降级为"引导式"也不阻塞主流程）。

### 难点 D（**新增·工程面**）：数据质量监控（Must，FR-36）
- **问题**：原方案只谈"数据采集"，v1.2 把"成功率/时效/对账误差监控+告警+看板"定为 Must，等于新增一个**运维子系统**。
- **解决**：采集流水线统一产出运行日志（每次拉取的成功/耗时/对账误差），定时聚合看板 + 阈值告警；与"数据错了比没有更糟"原则一致，建议**从 M1 起就埋点**。
- **风险**：中（工作量，不阻塞可行性）。

### 难点 E（**新增·数据噪声**）：逐股舆情（来源+时间）治理
- **问题**：逐股粒度 + 来源 + 时间，噪声与重复更高；需避免把单一负面新闻放大为"基金风险"。
- **解决**：① 多源交叉 + 情感标注 + 来源/时间强制落库；② 舆情仅作"提示"不输出确定性建议；③ 数据不足标"暂不确认"；④ 周评由 AI 统一聚合，避免散点误导。
- **风险**：中（与 v1.1 舆情难点同源，粒度更细）。

### 常规难点（保留，风险可控）
- **免费数据源稳定性**：锁版本 + Tushare fallback + 告警 + 缓存。
- **复权净值（极易错）**：统一后复权口径；单测已知分红案例；定投强制复权。
- **指标/归因准确性**：empyrical+statsmodels 引 + 自研对账；Brinson 用季报持仓+基准；与公开值误差<0.5%。
- **回测过拟合**：时间顺序回放；保留清盘样本；样本外验证。
- **大模型幻觉与成本**：RAG 约束 + 缓存 + 低价模型 + 超时降级。
- **模拟交易正确性**：复用复权逻辑；构造序列单测；与公开模拟盘抽样对账。
- **实时性 vs 批处理**：净值日更、盘中估算可选、AI/舆情定时；批处理架构即可；相似去重仅在结果集内计算，性能无忧。

## 十、可行性结论与建议（v1.2）

> **技术可行、数据可靠可用、算法选型清晰、成本极低、风险可控。** BRD v1.2 的 12 模块（含仪表盘、风险与监控）+ FR-D1~D6 + FR-01~48，在现有免费数据/接口/算法/LLM/RAG 条件下**均可实现，无付费硬依赖**。grill-me 相对 v1.1 抬高的是"数据域数量"与"方法学清晰度"，而非"能否做"。**真正需要在实现期重点投入的只有 4 项**：NL 选基硬 SLA（C）、风格箱交叉验证（B）、PEG/ERP 方法学定义（A）、数据质量监控工程（D）——均属"可解但需认真对待"，不构成可行性否决项。
