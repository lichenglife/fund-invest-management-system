## 1. 评估方法

### 1.1 复杂度评分维度（每维 1–5，5 最高）

| 维度 | 含义 |
|------|------|
| A 算法/数学 | 算法、数学推导、统计方法的复杂程度（百分位排名、Brinson、回测、归因等） |
| B 外部依赖/不确定性 | 对 LLM、外部 API、网络的不确定性与失败率（SLA、429、数据缺失） |
| C 并发/性能 | 并发模型、多进程/多线程、缓存、分布式锁的复杂程度 |
| D 数据模型/ETL | 数据建模、清洗、幂等 upsert、跨源对齐的难度 |
| E 业务规则复杂度 | 投资领域业务规则、阈值、红黄绿判定的设计与可解释难度 |
| F 前端/UX | 页面交互、可视化、实时性的复杂度 |
| G 集成耦合 | 被其他模块依赖、跨模块一致性与权威源约束的强度 |

> 综合复杂度 = 各维得分加权（A/B/E 权重 1.5，其余 1.0）后归一化到 0–100。

### 1.2 编码就绪度判定（rubric）

逐模块检查 7 项是否**已具备可直接编码的精度**（✓ 已具备 / △ 部分具备 / ✗ 缺失或冲突）：

| 项 | 检查内容 |
|----|----------|
| R1 接口契约 | 输入/输出字段、类型、枚举已在 §2.21 或模块 §3.x 明确 |
| R2 数据模型 | 表/字段/DDL 已在 §2.20 明确 |
| R3 算法步骤 | 精确公式 + 计算步骤 + 输入数据来源已给出（非仅描述） |
| R4 边界与异常 | 缺失值/失败/降级/口径未定义等边界已有处理约定 |
| R5 并发边界 | 并发模型、锁、缓存一致性已明确（§2.22 / §3.x.8） |
| R6 测试验收 | 可量化的验收/对账基准（test oracle）已定义 |
| R7 外部依赖 | 外部 API/LLM 的接入、兜底、配额已明确 |

**就绪度结论**：7 项中 ✗≥1 或存在**跨文档口径冲突** → **不可直接编码**，须出技术方案。

## 4. 决策：需单独形成技术方案的模块

按用户要求，对**高难且不可直接编码**的模块单独设计。本轮产出 6 份技术方案：

| 序号 | 技术方案 | 对应模块 | 核心待解问题 |
|------|----------|----------|--------------|
| TP-01 | 评估引擎（五因子评分 + Brinson 归因 + PEG/ERP 代理） | 3.3 | 因子口径对齐、原始指标定义、横截面百分位与批算/在线一致性、Brinson 数据流、PEG/ERP 代理代码 |
| TP-02 | NL 自然语言选基 | 3.4 | 条件词表全集、澄清状态机、规则兜底、SLA 评测内嵌 |
| TP-03 | 组合多层级诊断（红黄绿） | 3.6 | 五维阈值判定表、聚合与整体评级合成 |
| TP-04 | 回测引擎（定投 + 组合） | 3.5/3.6 | `_run_dca` 步骤、防未来函数、费率/分红、再平衡 |
| TP-05 | 宏观市场认知底盘 | 3.7 | 高位四维排查、股债中枢建议判定表 |
| TP-06 | AI 智能助手（RAG + 周报） | 3.11 | RAG 建库/检索、周报 worker、对话上下文 |

> **备注（建议补充，非阻塞）**：3.9 持仓穿透的「财务四维卡」建议在实现期补字段级定义（来源/报告期/四维度指标），其余中低模块按现有设计可直接编码。

## 5. 关键阻塞项（须先决解决）

| 编号 | 阻塞项 | 影响 | 建议处置 |
|------|--------|------|----------|
| BK-1 | **五因子口径三文档冲突**（BRD/技术规格=ret/risk/perf/scale/manager；详细设计=ret/risk/style/cost/scale） | 评估引擎、筛选器、仪表盘、组合全部依赖评分，命名不一对齐将导致跨模块脏数据 | 以 BRD/技术规格为准（ret/risk/perf/scale/manager），修订详细设计 §3.3.8.1，并在 §2.21 统一字段枚举 |
| BK-2 | **各因子原始指标未定义**（ret/risk/perf/scale/manager 各自对应哪个底层指标） | 评分不可复现、不可对账 | TP-01 给出指标映射表（年化收益/最大回撤/Sharpe/规模/任职回报等） |
| BK-3 | **横截面百分位 universe 与「在线单基 vs 批算」未对齐** | 在线查询与夜算结果可能不一致，违背 ADR-002 唯一权威源 | TP-01 明确：批算产出全市场百分位分位表缓存，在线查询复用分位表而非重算 |

> BK-1/2/3 为最高优先级，须在 Phase 1 评估引擎子任务（P1-03a~d）启动前闭合。
