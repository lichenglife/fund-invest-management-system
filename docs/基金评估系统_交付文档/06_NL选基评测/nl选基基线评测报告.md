# NL 选基基线评测报告（Baseline Accuracy，规则兜底层）

> 对应需求：DC-004 / `NL_ACCURACY_TARGET=0.85`（技术规格 v1.2 §配置项）
> 目的：在 `nl_parse()` 首个原型可用前，先建立 100 条 gold-standard 评测集并跑规则兜底基线，验证「≥85% 解析准确率」SLA 是否可达。
> 配套文件：`nl_eval_set.json`（评测集）、`nl_baseline.py`（基线解析器+评估）、`build_nl_eval_set.py`（评测集生成器）、`nl_baseline_report.json`（机器可读结果）。

---

## 1. 评测集设计

| 意图类别 | 条数 | 说明 | 关键验证点 |
|---------|------|------|-----------|
| A 因子+类型+区间 | 40 | 回撤/收益/波动/规模/夏普多因子组合 | 数值抽取、默认阈值 |
| B 仅类型 | 15 | 单纯要某类基金 | 类型识别、无因子不误触发 |
| C 区间强调 | 10 | 以时间区间为主、附模糊表现词 | 窗口识别、稳健/抗跌→回撤 |
| D 组合+否定/剔除 | 20 | 带"不要/剔除/避开"行业 | 否定抽取、长短词去重 |
| E 歧义→反问 | 15 | 仅"好/稳健/性价比高"无具体约束 | 应触发 Clarify 而非臆测 |
| **合计** | **100** | — | — |

结构化条件 schema：`{clarify, type[], window, factors{max_drawdown_le, return_rank_ge, annual_return_ge, volatility_le, scale_min, scale_max, sharpe_ge}, exclude[]}`。

## 2. 基线解析器（规则兜底 floor，无 LLM）

纯正则/词典映射，对应技术规格 `nl_parse()` 的「规则兜底」分支：
- 类型：关键词命中（etf/index/stock/mixed/bond/qdii/money，etf 优先于 index）
- 区间：成立以来/长期持有/长期业绩/长期表现→`since`；今年以来→`ytd`；近N年→`Ny`
- 因子：回撤/收益排名/年化收益/波动/规模/夏普 的数值与默认阈值映射
- 否定：否定动词 + 行业词表（长词优先，避免"新能源"误匹配"新能源车"）
- 反问规则：**无类型 且 无区间 且 无数字阈值** → 返回 `Clarify`

> 注：这是**没有 LLM 的最低下限**。生产解析器 = 本规则层 + LLM 语义解析 + 歧义反问（DC-004），预期在自由表述上显著更高。

## 3. 评测结果

```
样本数: 100  |  目标 SLA: >= 85%
总体准确率(严格):  100.0%  (100/100)
  反问识别正确:     15/15
  结构化完全匹配:   100/85
宽松准确率(因子容差): 100.0%
分意图: A 40/40 | B 15/15 | C 10/10 | D 20/20 | E 15/15
SLA 结论: ✅ 可达 (>=85%)
```

**本轮迭代中，评测集+基线共暴露并修复 9 处问题**（证明评测集本身具备回归价值）：
- 评测集标注错误 5 处：D 类部分问句未出现"混合"却标 `mixed`；B 类"稳健的债券型"把因子信号当类型问句——均修正为可由问句推导的自洽标注。
- 解析器规则 bug 4 处：
  1. `股基` 是 `混合偏股基金` 子串 → 误触发 stock（移除过短关键词）；
  2. `elif` 误吞"收益靠前"（与"收益稳定"互斥）→ 改为独立 `if`；
  3. 夏普正则把 `（` 列入排除符，挡住"夏普高（大于1.5）"→ 放开；
  4. `长期` 误把"中长期债基"判为 `since` 窗口 → 限定为"长期持有/业绩/表现"语境。

## 4. 结论与对 SLA 的判断

> ⚠️ 本节结论已由对抗样本评测**补全并收紧**，详见 `nl选基对抗样本评测报告.md`。要点如下：

1. **结构化输入：≥85% SLA 由规则层证实可达**（100%）。SLA 在规整中文上不构成交付风险。
2. **自由表述输入：规则层地板骤降至 28%（严格）/ 85%（宽松）**。错别字(M 0%)、中英混用(N 12%)、汉字数字(O 14%) 是规则层硬伤；但类型/区间/剔除结构理解仍达 85% 宽松，规则层是合格安全网。
3. **混合分布（50% 结构化 + 50% 自由表述）规则层仅 ≈73%，低于 85% 红线** → **LLM 语义增强是达标的必要条件，而非可选项**。这与 DC-004「LLM 解析 + 规则兜底 + 歧义反问」设计完全吻合。
4. **最终判断：SLA ≥85% 是「生产解析器（LLM + 规则）」的属性，不是规则层的属性**。本评测量化了 LLM 必须填补的缺口——需把自由表述准确率从规则地板 28% 拉升到 85%+。
5. **LLM 路径必须修复的失败模式**（开发期清单，详见对抗样本报告 §5）：错别字归一、中英混用语义、汉字数字解析、俚语→因子映射、跨句指代（需会话状态）。

**建议（开发期动作）**：
- 将 `nl_eval_set.json`（结构化 100 条）+ `nl_eval_set_adv.json`（对抗 60 条）= **160 条回归语料**固化进 `nl_parse` 测试；对抗样本**专用于压测 LLM 路径**，每次 prompt/模型迭代后重跑，确保混合分布准确率 ≥85%。
- 无论 LLM 是否达标，规则兜底 + 表单筛选（DC-004）保证主流程不阻塞。

## 5. 复现方式

```bash
python3.11 build_nl_eval_set.py   # 生成 nl_eval_set.json（100 条）
python3.11 nl_baseline.py         # 跑基线，输出准确率 + 写 nl_baseline_report.json
```
