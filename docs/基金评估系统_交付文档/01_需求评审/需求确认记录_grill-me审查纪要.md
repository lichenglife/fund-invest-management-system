# 需求确认记录 · grill-me 审查纪要

> **版本**：v1.1（全部 12 模块 grill-me 闭环）
> **日期**：2025年
> **文档类型**：需求决策可追溯性记录（Decision Traceability Log）
> **关联文档**：《业务需求说明书 BRD》（v1.2 起）、各模块技术规格
> **用途**：记录 grill-me 对需求的下钻过程——**考虑了哪些分支、最终选了哪个、为什么、遗留什么**。本纪要只承载"决策过程与理由"；**最终结论落入 BRD 第 5 章的 FR 文本**，两文档通过 FR 编号双向引用。

---

## 0. 使用说明（双向引用规则）

- **本纪要** = 决策推演（为什么这么定）。条目编号 `DC-00X`。
- **BRD** = 权威规格（定了什么）。FR 编号 `FR-Dx` / `FR-01~48`。
- 引用方式：
  - 本纪要中：`FR-D3 ← 见 DC-001`（该 FR 的推导见本纪要）
  - BRD 中：`（来源：DC-001）`（该 FR 经 grill-me 确认）
- **grill-me 结论**（选定分支 + 细化需求）→ BRD FR 文本。
- **grill-me 过程**（被否决分支、遗留问题）→ 仅留在本纪要，不污染 BRD。

## DC-001 · 仪表盘（首页总入口）

**触发**：用户认为仪表盘作为学习者入口"功能描述太简单"，希望学习者通过仪表盘就能了解更多内容（原诉求 3 点：① 展示不同类型基金排行榜、按不同条件展示不同维度；② 展示更新基金基础信息、作为学习基金知识的入口；③ 保持现有模块）。

**grill-me 探索的分支**

| 分支 | 内容 | 取舍 |
|------|------|------|
| A 总入口 | 仪表盘作为全站总入口，聚合账户/模拟状态、各模块快捷入口、待办（预警/复盘） | 采纳为定位：是"入口"不是"功能堆砌"，只放状态+快捷+提醒 |
| B 类型 Tab + Top10 综合评分 | 按基金类型（股票/混合/债券/指数/ETF/QDII…）分 Tab，每 Tab 内 Top10 按**综合评分**排序 | 采纳：评分用模块2可解释多因子评分，不照搬平台黑盒排名 |
| C 近期动态 + 学一基卡 | 近期动态卡（新发/净值异动/分红/估值信号）；"学一基"每日一只基金科普卡（一句话亮点+链接档案/词典） | 采纳：直接满足"学知识"诉求，把首页变成学习场 |
| D 状态→榜单→学习 布局 | 三段式信息架构：顶部账户/模拟状态 → 中部榜单 → 底部学习入口 | 采纳：符合"学习者入口"定位，信息由近及远 |
| E 折叠次要 | 高级/低频内容（原始数据导出、参数调优）折叠收起，保持首页清爽，深究时展开 | 采纳：避免首页过载 |

**最终决定**：采纳 A+B+C+D+E 综合方案。仪表盘 = **学习者友好型总入口**，不做成另一个功能页。

**产出 FR**（详见 BRD 5.3.0）：FR-D1（总入口聚合）、FR-D2（类型 Tab+Top10 综合评分）、FR-D3（近期动态卡）、FR-D4（学一基卡）、FR-D5（状态→榜单→学习布局）、FR-D6（折叠次要）。

**遗留问题 / Open Questions**
- OQ-1：综合评分在首页默认用哪套权重？→ 暂定"稳健学习版"默认权重，用户可在评估引擎内调节（见 FR-07）。
- OQ-2："学一基"内容由谁生成？→ 优先用数据中心真实档案自动摘要 + 指标词典链接，避免 AI 编造（落实 FR-46 溯源）。
- OQ-3：动态卡的"估值信号"红点是否与 FR-35 估值定投信号共用同一引擎？→ 是，避免双套逻辑。

## DC-002 · 基金数据中心

**触发**：对模块一（基金数据中心）下钻，明确"数据中心到底向学习者开放什么、怎么组织、怎么学"。

**grill-me 探索的分支**

| 分支 | 内容 | 取舍 |
|------|------|------|
| A 开放全类型 + ETF/LOF | 不只股票/混合，开放指数/ETF/LOF/债券/QDII/货币/FOF 全类型；ETF/LOF 纳入场内数据（折溢价、场内价） | 采纳：覆盖全才能"对比选择"，ETF/LOF 是学习利器重点 |
| B 搜索 + 分类树 + 发现入口 | 代码/拼音/名称搜索；左侧分类树（类型→主题→风格）；"发现"入口（按信号/按榜单/按学习推荐） | 采纳：解决"找不到"，发现入口承接仪表盘导流 |
| C 档案分组 + 字段解释 | 档案信息分组（概览/费率/规模/经理/持仓/风险）；每个专业字段 hover 显示释义（? 解释 tooltip） | 采纳：降低学习门槛，把"看不懂"变"点一下就懂" |
| D 净值复权 + 下载 + 盘中估算 | 单位净值/累计净值/复权净值切换；CSV/Excel 下载；盘中估算（估值涨跌% + 估算净值） | 采纳：数据可自分析，回应"数据不能自分析"痛点 |
| E 前十大 + 行业分布 跳⑨ | 展示前十大重仓股（占比）、行业分布图，点击跳转**持仓穿透与舆情（BRD 模块 11）**做深度研究 | 采纳：建立"基金→股票"研究链路（注：用户口述"跳⑨"指持仓穿透模块，对应 BRD 模块 11） |
| F 经理风格箱 | 基金经理九宫格风格箱（大盘/中盘/小盘 × 价值/平衡/成长）+ 任职回报/代表基 | 采纳：便于"选经理"，承接模块2风格箱能力 |

**最终决定**：采纳 A~F 全六分支。数据中心从"基金库"升级为"可学、可查、可下钻"的研究底盘。

**产出 FR（增强）**：FR-01（全类型+搜索+分类树+发现，落 A/B）、FR-02（复权+下载+盘中估算，落 D）、FR-03（档案分组+字段解释，落 C）、FR-04（前十大+行业分布+跳穿透，落 E，优先级由 Should 升 Must）、FR-05（经理风格箱，落 F）。

**遗留问题 / Open Questions**
- OQ-4：盘中估算的数据延迟与免责如何标注？→ 复用 FR-46 全局溯源，标注"盘中估算仅供参考，以收盘净值为准"。
- OQ-5：ETF/LOF 场内价与净值来源是否同源？→ 优先 AkShare，Tushare 兜底（见技术可行性评估数据可靠性矩阵）。
- OQ-6：行业分布分类标准用申万一级还是中信？→ 暂定申万一级，可在设置切换（设计期再定）。

## DC-003 · 基金评估引擎

**触发**：对模块二（评估引擎）下钻，明确综合评分 / 风格箱 / Brinson / 研究指标的算法路径与边界（两轮 grill-me）。

**grill-me 决策（已确认）**

| 决策点 | 决定 | 理由 |
|--------|------|------|
| 评分权重（FR-07） | 系统给默认权重（收益30/风险25/性价比20/规模15/经理10）+ 用户可调，实时看因子分解 | 可解释且不让新手卡在配权重 |
| 风格箱（FR-08） | 持仓市值/估值成长因子判定九宫格 + 历史收益回归交叉验证 | 避免单方法误判 |
| Brinson 归因（FR-09） | 仅主动管理股混基；指数基金用跟踪误差/信息比率替代；债基不显示 | 归因对被动/债基无意义 |
| 研究指标（FR-45） | 分组卡片 + 阈值着色 + 一句话解读（αβ/跟踪误差/折溢价/PEG/ERP） | 降低学习门槛 |
| 区间基准（FR-06） | 默认滚动 3 年；基准按类型自动选宽基（股→沪深300/混→中证800/债→中债总财富），可改 | 统一且合理默认 |
| 可信度（FR-06/45） | 开源库交叉验证，误差 >0.5% 标红，所有数值标数据截至 | 让用户信得过 |
| 联动边界 | 评估引擎为唯一评分权威源，筛选器/仪表盘只读引用 | 避免多套评分矛盾 |
| 异常处理 | 降级提示不阻塞（区间短/基准错/缺失/延迟各有提示） | 体验优先 |

**产出/增强 FR**：FR-07（默认权重+可调+因子分解）、FR-08（持仓为主+收益校验）、FR-09（仅主动股混基）、FR-45（卡片+阈值+解读）、FR-06（默认3年+自动基准+交叉验证标红）。

**遗留问题 / Open Questions**
- OQ-7：默认权重具体比例是否需投资导师审定？→ 暂定上述比例，落地前由导师确认。
- OQ-8：收益回归交叉验证用 CAPM 还是 Fama-French 三因子？→ 暂定 CAPM（与 αβ 一致），可升级。
- OQ-9：折溢价实时性标注频率？→ 场内数据盘中刷新，标注"盘中"。
