# 基于大模型与 AI Coding 的基金评估 & 量化交易系统规划

> **定位**：面向个人投资者（非机构），用较低成本搭建一套"选基 + 评估 + 监控"的辅助决策系统。
> 大模型负责**理解、解读、生成**；量化模型负责**计算、排序、回测**；人负责**最终决策**。
>
> **核心原则**：AI 是放大镜和加速器，不是印钞机。系统产出的是"投资依据"，不是"投资保证"。

## 一、目标定位：先想清楚要做什么

"选基"和"量化交易"是两套不同复杂度的系统，规划阶段必须分开定边界：

| 维度 | 基金评估系统 | 量化交易系统 |
|------|------------|------------|
| 核心目标 | 从几千只基金中筛出好基金 + 持续跟踪 | 用策略自动产生买卖信号/自动执行 |
| 技术难度 | ⭐⭐⭐（中等） | ⭐⭐⭐⭐⭐（高） |
| 数据需求 | 基金净值、持仓、经理、风格 | 还需分钟级行情、交易接口、风控引擎 |
| 合规风险 | 低（自看自用） | 高（实盘涉及券商资质、适当性） |
| 建议优先级 | **先做这个** | 评估系统成熟后再考虑 |

**给普通人的建议**：
- 第一阶段只做**基金评估系统**，它直接解决你"不知道选什么基金、买了之后怎么跟踪"的痛点。
- 量化交易（自动下单）建议作为第二阶段甚至远期目标，因为实盘交易对系统稳定性、延迟、合规要求极高。

## 三、数据层规划（系统的地基）

> **一句话经验**：80% 的项目死在数据上。数据质量决定系统上限，模型只是锦上添花。

### 3.1 需要采集的数据类型

| 数据类别 | 具体字段 | 更新频率 | 推荐数据源 |
|----------|----------|:------:|-----------|
| **基金基础信息** | 代码、名称、类型、成立日、规模、费率、托管行 | 每日/周 | Tushare、AkShare、天天基金 |
| **基金净值** | 单位净值、累计净值、日涨跌幅 | 每日收盘后 | AkShare（免费）、Tushare |
| **基金持仓** | 前十大重仓股/债、行业分布、仓位 | 季度（年报/半年报更全） | Tushare、聚宽、东方财富 |
| **基金经理** | 姓名、从业年限、在管产品、管理规模、历史业绩 | 变动时 | 天天基金、Wind（付费） |
| **市场行情** | 指数（沪深300/中证500等）、个股、债券收益率 | 日/分钟 | AkShare、Tushare、baostock |
| **宏观数据** | GDP、CPI、利率、M2、社融 | 月/季 | 国家统计局API、AkShare |
| **文本类** | 基金季报/年报、经理访谈、财经新闻、股吧舆情 | 不定期 | 爬虫、新闻API、RSS |
| **估值数据** | 指数PE/PB分位数、股债利差 | 每日 | 且慢、蛋卷、理杏仁 |

### 3.2 数据源分层（成本由低到高）

```
免费层（MVP 首选）：
  ├── AkShare    → 最全的免费金融数据接口（Python库，开箱即用）
  ├── Tushare    → 注册免费积分可用基础数据，积分为门槛
  ├── baostock   → 历史行情稳定
  └── 天天基金/东方财富 网页接口 → 净值、估值实时抓取

付费层（进阶）：
  ├── Tushare Pro（积分制，几千元/年可拿全量）
  ├── 聚宽/优矿（量化平台，含回测）
  └── Wind / Choice（机构级，贵，个人一般不需）

不建议个人碰：
  └── 实时 tick 数据（贵且对选基无意义）
```

### 3.3 存储方案

| 数据类型 | 存储 | 理由 |
|----------|------|------|
| 基金基础信息、评分结果 | PostgreSQL | 结构化、支持复杂查询 |
| 净值时间序列 | PostgreSQL 分区表 或 Parquet 文件 | 时序数据量大 |
| 文本/研报/问答 | 向量数据库（Chroma/Milvus/Qdrant） | 支持 RAG 语义检索 |
| 缓存 | Redis | 接口限流、热点数据 |

## 四、基金评估模型层（核心引擎）

这一层把上一轮指南里的"基金筛选五步法"变成**可计算、可排序的量化指标**。

### 4.1 指标体系（按维度拆分）

**A. 收益指标**

| 指标 | 公式/含义 | 用途 |
|------|-----------|------|
| 年化收益率 | (期末/期初)^(250/交易日)-1 | 绝对盈利能力 |
| 超额收益 | 基金收益 - 业绩比较基准 | 跑赢基准的能力 |
| 夏普比率 | (收益-无风险利率)/波动率 | 单位风险收益（性价比） |
| 卡玛比率 | 年化收益/最大回撤 | 承受极端风险的回报 |
| 索提诺比率 | (收益-无风险)/下行波动 | 只看下跌风险的性价比 |

**B. 风险指标**

| 指标 | 含义 | 关注点 |
|------|------|--------|
| 最大回撤 | 历史最高点→最低点跌幅 | "你最多能亏多少" |
| 年化波动率 | 收益标准差 | 净值颠簸程度 |
| 下行风险 | 仅负收益的标准差 | 持有体验 |
| VaR/CVaR | 一定置信下的可能损失 | 尾部风险 |

**C. 基金经理评估（主动基金核心）**

```
评估维度：
  ① 从业年限（>5年，经历牛熊）
  ② 在管规模（10-150亿为宜）
  ③ 代表产品年化（>10%，且排名前1/3）
  ④ 最大回撤控制（<同类平均）
  ⑤ 风格稳定性（用持仓归因，看是否"挂羊头卖狗肉"）
  ⑥ 择时能力（TM模型 / 择时系数）
  ⑦ 选股能力（用Brinson归因的选股部分）
```

**D. 风格与归因**

- **风格箱（Style Box）**：大盘/中盘/小盘 × 价值/平衡/成长（用净值回归法判定）
- **Brinson 归因**：把超额收益拆成"资产配置收益 + 个股选择收益 + 交互收益"
- **行业暴露**：计算持仓行业权重 vs 基准的偏离

### 4.2 多因子综合评分模型

```python
# 伪代码：综合评分逻辑
def score_fund(fund):
    # 各维度归一化到 0-100
    s_return  = normalize(fund.sharpe, peer_group)        # 收益性价比 30%
    s_risk    = normalize(-fund.max_drawdown, peer_group) # 风险控制 25%
    s_manager = score_manager(fund.manager)               # 经理能力 20%
    s_scale   = score_scale_fit(fund.scale)               # 规模适配 10%
    s_cost    = normalize(-fund.fee_rate, peer_group)     # 费率成本 10%
    s_style   = score_style_stability(fund)               # 风格稳定 5%
    return 0.30*s_return + 0.25*s_risk + 0.20*s_manager \
         + 0.10*s_scale + 0.10*s_cost + 0.05*s_style
```

> **关键点**：同类型基金内部比较（股票型 vs 股票型），不要跨类型比夏普。
> **防过拟合**：评分权重应基于投资逻辑设定，不要用历史收益去"训练"权重（那等于用过去预测未来，必然过拟合）。

### 4.3 聚类与相似度

- 用持仓向量做余弦相似度，找出"换个名字但持仓雷同"的基金（避免重复配置）
- 用净值相关性做聚类，帮用户做组合分散

## 五、大模型应用层（AI 的差异化价值）

这是 AI Coding + LLM 真正带来质变的地方——把"数据"变成"人能读懂的决策依据"。

### 5.1 六大应用场景

| 场景 | 做什么 | 技术实现 | 价值 |
|------|--------|----------|------|
| **1. 基金季报/年报解读** | 把几十页PDF提炼成"这只基这季度干了啥、变了啥" | LLM + 文档解析（PDF→文本→摘要） | 省去读研报时间 |
| **2. 自然语言选基** | "帮我找回撤<15%、年化>10%的红利基金" → 自动生成查询 | LLM + Text2SQL/Text2API | 不用写代码也能筛选 |
| **3. 基金经理画像** | 汇总经理所有产品、风格、言论，生成人物卡 | LLM + 多源信息聚合 | 了解"把钱交给谁" |
| **4. 持仓变化分析** | 对比两期持仓，说清"加了什么、减了什么、为什么" | LLM + Diff 逻辑 | 跟踪调仓意图 |
| **5. 市场舆情/情绪** | 抓取新闻股吧，给市场/行业打情绪分 | LLM + 情感分析 | 辅助择时参考 |
| **6. 自动投资周报** | 每周汇总持仓、收益、市场、预警 | LLM + Agent 编排 | 持续跟踪不遗漏 |

### 5.2 RAG 知识库（让 AI 基于真实数据回答）

```
架构：
  文档（招募说明书/定期报告/你的投资笔记）
        ↓ 切片（chunk）
        ↓ Embedding（嵌入向量）
   向量数据库（Chroma/Qdrant）
        ↑ 用户问题
   检索相关片段 → 拼进 Prompt → LLM 生成答案

效果：AI 回答"这只基金的投资范围是什么"时，基于真实合同而非瞎编。
```

### 5.3 Agent 编排（进阶）

```
投资助理 Agent 工作流：
  用户："我这周持仓怎么样？有风险吗？"
    → 调用【持仓查询工具】拿最新数据
    → 调用【市场扫描工具】看有无重大事件
    → 调用【预警检查工具】比对阈值
    → LLM 综合生成周报 + 风险提示
```

## 六、量化交易系统（可选增强）

仅在你基金评估系统稳定运行 6 个月以上、且确实想做策略交易时再考虑。

| 模块 | 内容 | 工具 |
|------|------|------|
| 回测框架 | 用历史数据验证策略 | backtrader / vectorbt / 聚宽 |
| 因子库 | 估值、动量、质量等因子 | 自建 + pandas |
| 信号生成 | 定投加倍、止盈止亏规则 | 规则引擎 |
| 实盘接口 | 券商 API 下单 | 恒生/同花顺开放平台（需资质） |
| 风控闸 | 单日最大亏损、仓位上限 | 自研 |

> **重要提醒**：A 股实盘交易接口有合规门槛，个人通过券商开放平台（如华宝、雪球条件单）做"半自动"更实际。全自动高频交易不是个人玩家的赛道。

## 七、工程实现：用 AI Coding 加速开发

### 7.1 开发节奏（用 AI Coding 提效）

```
第1步：用 AI Coding 生成数据层
  → 提示词："用 AkShare 写一个有每日更新基金净值的 Python 脚本，存 PostgreSQL"
  → 工具：Cursor / CodeBuddy / Claude + 本地 IDE

第2步：用 AI Coding 生成指标计算模块
  → 提示词："实现夏普、卡玛、最大回撤、索提诺的计算函数，带单元测试"

第3步：用 AI Coding 生成评分与 API
  → 提示词："用 FastAPI 写选基接口，支持按回撤、年化、类型筛选排序"

第4步：用 AI Coding 生成前端仪表盘
  → 提示词："用 Streamlit 做一个基金排行榜页面，展示评分、回撤、经理信息"

第5步：接入大模型
  → 提示词："用 LangChain 接入 Claude/通义，实现'用中文问句筛选基金'的接口"
```

### 7.2 AI Coding 最佳实践

- **分模块给 AI 写**：不要一次性让 AI 写整个系统，按数据/指标/API/前端逐块生成
- **必须带测试**：让 AI 同时生成单元测试，数据 bug 比代码 bug 更隐蔽
- **让它解释**：AI 生成的复杂指标代码，要求它逐行注释，避免"黑箱"
- **人工复核模型逻辑**：评分权重、归因方法这些核心逻辑，必须由你（投资专家身份）确认，不能让 AI 自由发挥

## 八、风控与合规

### 8.1 系统自身风险

| 风险 | 表现 | 应对 |
|------|------|------|
| 数据错误 | 净值缺失、复权错误 | 数据校验 + 异常告警 |
| 回测过拟合 | 历史漂亮实盘崩 | 样本外测试 + 简单优先 |
| 模型漂移 | 市场变了模型失效 | 定期重训 + 人工复核 |
| 大模型幻觉 | AI 编造基金数据 | RAG + 关键数字必须来自数据库 |

### 8.2 使用合规

```
⚠ 个人使用 vs 对外服务 完全不同：
  个人自看自用：基本无限制
  对外提供选基建议：涉及"投资咨询"资质，需持牌

⚠ 系统定位：
  → 标注"本系统输出仅供个人研究参考，不构成投资建议"
  → 不直接给"买XX基金"的指令，给"评估维度+数据"
  → 最终买卖决策权在人
```

## 给普通人的落地建议（最重要）

1. **不要想着一步到位**。先做出阶段一的"能筛选基金"版本，比规划完美架构更有价值。
2. **数据 > 模型 > AI**。先把净值数据稳定跑通，评分模型才有意义，大模型才有素材。
3. **AI 写代码可以，AI 定投资逻辑不行**。评分权重、风控阈值这些，必须由你基于投资知识拍板。
4. **系统再好也只是依据**。最终买不买、买多少、何时卖，是你自己的决策，系统不能替你承担亏损。

> 一句话总结规划：**数据采集打地基 → 指标评分建引擎 → 大模型做解读与交互 → 风控合规全程护航 → 用 AI Coding 快速迭代**。
