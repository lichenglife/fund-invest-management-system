## 1. 引言

### 1.1 编写目的
本文档旨在明确"个人基金评估与模拟交易系统"（以下简称"本系统"）的业务目标、用户角色、功能范围与验收标准，作为后续产品设计、技术设计与开发交付的依据。本文档对规划的 **12 个功能模块（含仪表盘首页 + 11 大功能模块）** 逐一进行需求探索分析，并达到 FR + 七要素 + User Story + 验收标准 的粒度。

## 2. 项目背景与业务现状

### 2.1 业务背景
公募基金超 14000 只，普通投资者面临"选择困难、不懂评估、缺乏练习"三大痛点。现有销售平台（天天基金、雪球、支付宝）本质是基金超市，评估为成交服务，普遍存在收益排名导向、评估黑盒、无模拟闭环、数据封闭等问题。本系统定位**个人学习 + 模拟交易 + 基金评估**，不销售基金，评估逻辑纯粹服务于"做对决策"。

### 2.2 当前痛点与问题

| 用户痛点 | 竞品现状 | 本系统对策 |
|----------|----------|-----------|
| 不知道选什么 | 排行榜诱导追高 | 多因子评分 + 自定义权重 |
| 买了不会跟踪 | 只有净值曲线 | 评估引擎 + 预警 + 周报 |
| 没地方练手 | 无模拟盘 | 虚拟账户闭环 |
| 看不懂为何涨跌 | 无归因 | Brinson 归因 + 持仓穿透 |
| 不懂宏观/仓位 | 无宏观视角 | 模块九 宏观市场认知底盘 |
| 亏了不知何时回本 | 无测算 | 模块十 回本测算/情景推演 |
| 数据不能自分析 | 数据封闭 | 全量可导出/API |

### 2.3 项目目标
为个人投资者提供"学指标 → 懂宏观 → 筛基金 → 模拟买 → 深评估 → 看穿透 → 复盘改进"的完整闭环。

**成功度量指标（KPI）**：

| 指标 | 目标值 | 度量方式 |
|------|--------|----------|
| 基金数据覆盖率 | ≥ 全市场 95% | 系统库/市场总数 |
| 核心指标计算准确率 | 与公开源对账误差 < 0.5% | 抽样对账 |
| 宏观/市场数据更新时效 | T+1（日频），月度指标 T+15 内 | 更新日志 |
| 模拟交易成交准确率 | 100% | 构造序列单测 |
| 自然语言选基准确率 | ≥ 85% | 人工评测 100 条 |
| 组合诊断规则覆盖率 | 100% 落地诊断规则阈值 | 规则对照 |
| 系统年运行成本 | < 500 元 | 账单统计 |

### 2.4 假设与约束条件
- **假设**：免费数据源（AkShare/Tushare/国家统计局）持续可用；持仓/财务季更；单用户自用。
- **约束**：不销售基金、不对外荐股；云预算 < 500 元/年；开发 2~3 个月业余时间。

## 4. 业务流程与场景

### 4.1 现有流程（As-Is）
用户 → 销售平台看榜 → 凭感觉买 → 焦虑 → 追涨杀跌 → 亏损。

### 4.2 目标流程（To-Be）
用户 → 看宏观定仓位（模块九）→ 学指标 → 筛基金 → 模拟买 → 深评估（评分/归因/回本/情景）→ 持仓穿透（模块十一）→ 跟踪预警 → 复盘对照 → 跑赢基准再实盘。
> 仪表盘（首页总入口）作为上述流程的统一入口，聚合状态、榜单与学习入口（见 5.3.0）。

### 4.3 关键业务场景
| 编号 | 场景 | 描述 |
|------|------|------|
| S1 | 选基评估 | "回撤<15%、年化>10%"筛选 |
| S2 | 模拟练手 | 100 万虚拟资金定投模拟 |
| S3 | 深度归因 | 查看"赚的是选股还是运气" |
| S4 | 组合诊断 | 核心-卫星组合，提示行业集中 |
| S5 | 宏观定仓 | 看宏观/情绪，决定股债中枢 |
| S6 | 回本测算 | 模拟亏损后看"回本需涨多少" |
| S7 | 持仓穿透 | 看重仓股舆情与财务健康 |
| S8 | 逆向提醒 | 估值高位提醒减仓而非追买 |
| S9 | 首页学习 | 进首页即见榜单+学一基+动态 |

### 5.3 各功能模块详细需求

---

#### 5.3.0 模块【首页】仪表盘（总入口）★v1.2 新增（DC-001）

**功能描述**：作为全站统一入口，面向学习者聚合"账户/模拟状态 + 各模块快捷入口 + 待办提醒"，并以"状态 → 榜单 → 学习"三段式布局呈现：顶部展示用户当前状态，中部按基金类型展示 Top10 综合评分榜单与近期动态，底部提供"学一基"等学习入口。不做成另一个功能页，而是"入口 + 学习场"。

**业务规则**
- BR-D.1 总入口聚合：展示虚拟账户净值/收益、待办（未读预警、待复盘）、模块快捷入口（数据中心/筛选/评估/模拟/组合/学习…）
- BR-D.2 类型 Tab + Top10：按基金类型（股票/混合/债券/指数/ETF/LOF/QDII/货币/FOF）分 Tab；每 Tab 内 Top10 按**综合评分**降序（评分口径复用 FR-07，可解释、可点开看因子）
- BR-D.3 近期动态卡：聚合新发基金、净值异动（日涨跌超阈值）、分红公告、估值信号触发（复用 FR-35）；按时间倒序
- BR-D.4 学一基卡：每日一只基金，一句话亮点 + 链接至档案（FR-03）/ 指标词典（FR-25）；内容取自真实档案自动摘要，禁止 AI 编造
- BR-D.5 三段式布局：顶部状态区 → 中部榜单+动态区 → 底部学习区（学一基/学习路径/案例回放入口）
- BR-D.6 折叠次要：高级/低频入口（原始数据导出、参数调优、API）折叠收起，展开可见
- BR-D.7 所有展示数据标注来源与截至时间（落实 FR-46）

**输入输出**

| 输入 | 输出 |
|------|------|
| 用户登录态 / 刷新 | 状态卡 + 类型Tab榜单 + 近期动态 + 学一基卡 |
| 点击 Tab / 基金 | 跳转对应模块详情 |

**前置/后置**：前置各模块数据已就绪；后置为各功能模块的统一导流入口。
**异常边界**：无数据/首访显示引导；某模块异常不影响首页其余区块（区块级降级）；动态数据延迟标注时效。

**输入输出**

| 输入 | 输出 |
|------|------|
| 研报/基金代码/问题 | 摘要/画像/周报/答案（含来源标注） |

**前置/后置**：前置数据中心/评估/舆情；后置供学习。
**异常边界**：RAG 无相关文档答"无依据"；LLM 失败降级；不输出确定性买卖建议。
**优先级**：Could（P2）。
**验收标准**：① 解读/画像/周报可用；② 输出含来源标注与免责；③ 无依据时明确拒答。

**User Story**
- 作为**进阶评估者**，我想要把一份研报丢给助手要"三句话要点"，以便快速消化。
- 作为**入门学习者**，我想要问"什么是核心-卫星"，并得到带出处的解释，以便可信地学习。

#### 5.3.8 模块八：风险与监控（DC-009 已 grill-me）

**功能描述**：守住边界。提供风险偏好测评、预警中心、估值定投信号、数据质量监控，以及市场高位信号排查与全局数据溯源免责。

**业务规则**
- BR-8.1 风险偏好测评：问卷判定稳健/均衡/积极，**联动默认配置建议与模拟交易起点仓位**（DC-009）
- BR-8.2 预警中心：**聚合多类预警（估值/回撤/净值异动/持仓变化），站内展示 + 可设提醒频率**（DC-009）
- BR-8.3 估值定投信号：**PE 分位→定投倍数映射（低多投/高少投/极高停投），站内信号红点 + 可订阅**（DC-009）
- BR-8.4 数据质量监控：**采集成功率/时效/对账误差监控，异常实时告警 + 质量看板**（Must / DC-009）
- BR-8.5 市场高位信号排查：估值（盈利能否消化）、通胀（CPI>3% 利空）、资金面（持续流出）、政策（央行措辞转向）四维 → 输出"高位/中性/低位"（FR-38）
- BR-8.6 全局输出标注数据截至时间与免责声明（FR-46）

**输入输出**

| 输入 | 输出 |
|------|------|
| 用户配置/数据管道状态 | 预警列表 / 定投信号 / 高位判断 / 质量报告 |

**前置/后置**：前置全量数据；后置供仪表盘/组合/宏观。
**异常边界**：数据源失败触发质量告警；信号缺失标注。
**优先级**：Should（数据质量 Must，P0）。
**验收标准**：① 预警/信号可用；② 高位排查四维可用；③ 质量监控覆盖；④ 免责标注完整。

**User Story**
- 作为**入门学习者**，我想要在估值高位收到"少投而非追买"的提醒，以便逆向纪律。
- 作为**系统 Owner**，我想要数据更新失败立刻告警，以便及时修复而非给用户错误数据。

#### 5.3.9 模块九：宏观与市场认知底盘（SA-01/SA-03，DC-010 已 grill-me）

**功能描述**：先定仓位再选基。提供宏观指标、市场情绪与资金流、外围传导研判、市场高位信号排查，解决"重工具、轻宏观"缺口。

**业务规则**
- BR-9.1 宏观卡：**核心指标（PMI/CPI/利率/汇率 + 市场情绪）优先展示，其余（PPI/GDP）折叠可展开**，含趋势与"截至日期"（DC-010）
- BR-9.2 市场博弈：VIX、成交量、融资余额、南北向资金、ETF 申赎
- BR-9.3 外围传导：**优先展示隔夜美股/中概/A50 → 次日 A 股开盘研判**，休市标"暂无"（DC-010）
- BR-9.4 高位排查：复用 FR-38 四维信号，**输出 高位/中性/低位 + 一句话操作暗示**（与模块八共享引擎，DC-010）
- BR-9.5 **据宏观/情绪给股债中枢建议（如沪深300 PE 分位低→偏股），可跳转组合与配置**，落实"先定仓位再选基"（DC-010）

**输入输出**

| 输入 | 输出 |
|------|------|
| 无 / 刷新 | 宏观卡 + 情绪仪 + 外围提示 + 高位判断 |

**前置/后置**：前置数据中心已采宏观/资金流；后置供组合诊断、估值信号引用。
**异常边界**：宏观数据延迟（月度 T+15）标注"数据截至"；外围休市显示"暂无"。
**优先级**：Should（P1）。
**验收标准**：宏观/情绪/外围/高位四项均可用且标注时效。

**User Story**
- 作为**模拟交易者**，我想要先看"现在市场是高估还是低估"再决定股债比例，以便不盲目满仓。
- 作为**入门学习者**，我想要看懂 CPI 和利率对基金的影响，以便建立宏观直觉。

#### 5.3.10 模块十：单基深度实验室（SA-04/05/06，DC-011 已 grill-me）

**功能描述**：把"评估"变"推演"。提供回本测算、情景推演、策略对照，让学习者理解操作后果——学习利器核心。

**业务规则**
- BR-10.1 回本测算：`回本需涨 = |当前收益| / (1+当前收益)`（亏损时）；**输入当前收益率（亏损填负），自动输出回本需涨幅度 + 保守/基准/乐观三情景回本时间**（FR-40 / DC-011）
- BR-10.2 情景推演：**保守/基准/乐观三情景，各给目标点位 + 预期回报 + 对持仓影响**（FR-41 / DC-011）
- BR-10.3 策略对照：**持有/定投/波段/调仓/止损五策略卡片，各含适用条件 + 优劣 + 适合人群**（FR-42 / DC-011）
- BR-10.4 测算输入须来自数据中心真实净值，禁止编造
- BR-10.5 **测算结果可存笔记；亏损回本提示联动模拟交易持仓**，形成"亏了怎么办"闭环（DC-011）

**输入输出**

| 输入 | 输出 |
|------|------|
| 基金代码 + 当前收益 | 回本需涨幅度 + 三情景时间 |
| 基金代码 | 情景对比表 |
| 用户情况 | 策略对照建议 |

**前置/后置**：前置净值/评估数据；后置结果可存笔记。
**异常边界**：收益为正（无需回本）提示"已盈利"；数据缺失提示选交易日。
**优先级**：**Must（P0 强化）**。
**验收标准**：回本公式单测通过；三情景/策略表可读可解释。

**User Story**
- 作为**模拟交易者**，我想要买入亏损后立刻算"还要涨多少才回本"，以便停止恐慌。
- 作为**入门学习者**，我想要对比"一次性买入 vs 定投"在同一只基金上的结果，以便理解策略差异。

#### 5.3.11 模块十一：持仓穿透与舆情（SA-07/SA-08，DC-012 已 grill-me）

**功能描述**：从基金穿透到重仓股，做舆情扫描与财务透视，理解"基金为何涨跌"，衔接股票研究能力（承接 FR-04 跳转链路）。

**业务规则**

- BR-11.3 财务透视：**营收净利增速 / 毛利率 / 经营现金流 / 杠杆率 四维度卡片**（FR-44 / DC-012）
- BR-11.4 舆情总结：整体倾向 + 重点风险/正面催化（DC-012）
- BR-11.5 所有数据标注来源与截至时间（FR-46）
- BR-11.6 **更新触发：持仓季更、舆情日更；进入基金自动触发穿透，可手动刷新**（DC-012）

**输入输出**

| 输入 | 输出 |

**前置/后置**：前置持仓/新闻/财务数据；后置供 AI 周评引用。
**异常边界**：新闻源缺失标注"数据不足"；非交易日提示。
**优先级**：Could（P2）。
**验收标准**：舆情情绪标注准确，财务透视可读，来源可追溯。

**User Story**

- 作为**数据研究者**，我想要看重仓股的毛利率和现金流，以便判断基金经理"买的是不是好公司"。

## 6. 数据需求

### 6.1 关键业务对象与数据实体
- 基金 / 净值 / 持仓 / 经理 / 评分 / 模拟账户 / 预警 / 笔记
- **MacroIndicator（宏观指标）**：指标名、日期、数值、环比（PMI/CPI/PPI/GDP/利率/汇率）
- **MarketSentiment（市场情绪资金流）**：日期、VIX、成交量、融资余额、南北向、ETF申赎
- **SentimentNews（舆情新闻）**：股票代码、标题、来源、时间、情绪标签
- **StockFinancial（重仓股财务）**：股票代码、报告期、增速、毛利率、现金流、杠杆

### 6.2 数据来源与流向
```
AkShare/Tushare → 基金/净值/持仓/经理/财务 → PostgreSQL
AkShare/国家统计局 → 宏观指标 → PostgreSQL
AkShare → 市场情绪/资金流/外围 → PostgreSQL
新闻API/爬虫 → 舆情新闻 → PostgreSQL(+情感标注)
基金季报PDF → 爬虫 → 解析 → Chroma(向量库, RAG)
用户操作 → 模拟账户/笔记/配置 → PostgreSQL
```

### 6.3 数据量级预估
- 基金 ~14000；净值 ~3500 万行（<5GB Parquet）
- 宏观/情绪：千级/日频；舆情：万级新闻；财务：万级记录
- 向量库：季报解析后百万级 chunk

### 6.4 数据可靠性/准确性/时效性要求
- 净值/估值：**高准确、高时效（日频 T+1）**，来源 AkShare/Tushare
- 宏观：**极高准确、中时效（月度 T+15）**，来源国家统计局/AkShare
- 资金流/舆情：**中高准确、高时效（日频/实时）**，来源 AkShare/新闻API
- 财务/持仓：**高准确、低时效（季频）**，来源 Tushare/财报
- 所有实体须记录"数据来源 + 截至时间"字段，供 FR-46 展示
