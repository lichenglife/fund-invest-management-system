## 2. 重新设计方案

### 2.1 设计令牌 v2（单一权威源）

以 `app/static/style.css` 为**唯一源**，补齐刻度变量，并令 `app/utils.py` 颜色常量**单向对齐**（消除所有内联字面量）：

```css
:root{
  /* 品牌（保留翠绿专业风） */
  --brand-deep:#0A6B4A; --brand:#16A34A; --brand-bg:#F0FDF4;
  /* 涨跌语义（见 2.2 决策；此处以红涨绿跌为例） */
  --up:#E23B3B; --down:#16A34A; --up-bg:#FDE8E8; --down-bg:#F0FDF4;
  /* 状态/功能 */
  --warn-bg:#FEF9C3; --warn-fg:#B45309; --info-bg:#DBEAFE; --info-fg:#1D4ED8;
  --danger:#E23B3B; --danger-bg:#FDE8E8;
  /* 文字 */
  --text-title:#111827; --text-body:#374151; --text-muted:#6B7280;
  /* 间距刻度（4 基准） */
  --space-1:4px; --space-2:8px; --space-3:12px; --space-4:16px; --space-6:24px; --space-8:32px;
  /* 字号阶梯 */
  --text-xs:12px; --text-sm:13px; --text-base:14px; --text-lg:16px; --text-xl:20px; --text-2xl:28px;
  /* 圆角/阴影/焦点 */
  --radius:12px; --radius-sm:8px; --shadow:0 1px 3px rgba(0,0,0,.08);
  --focus:0 0 0 3px rgba(22,163,74,.45);
  /* 断点（见 2.4） */
  --bp-sm:640px; --bp-md:900px; --bp-lg:1200px;
}
```

`app/utils.py` 改为：`COLOR_UP/COLOR_DOWN/COLOR_BRAND...` 仅作**只读镜像**，新增 CI 断言禁止出现令牌外十六进制色。

### 2.2 配色语义决策（关键，需产品确认）

- **问题**：当前系统同时含"翠绿=正"与"红涨绿跌"两套语义 → 必须二选一且全局唯一。
- **建议（A 股标准）**：**涨=红、跌=绿**（数值方向）；品牌/选中态/正向 UI 强调仍用翠绿；健康状态绿=正常、红=异常（靠图标+语境区分，附图例）。这是国内基金/股票用户的事实预期，最符"合理性"。
- **备选**：若产品偏好更"冷静专业"的翠绿=正全局体系，亦可，但**必须唯一**。
- **流程红线**：若选红涨绿跌（推翻《前端原型》§5 现行"翠绿=正"意图），须**先更新原型§5 + 开发规范§10** → 该子项升 **C3 子流程（先改文档再实现）**；无论哪种，落地后 `utils.pct_color` 与 `kpi_card`/令牌必须一致。

### 2.3 组件库统一与复用审计

- **清点**（已实现）：`kpi_card / score_panel / ranking_table / brinson_chart / diagnosis_table / style_box / ui(metric_card/panel/status_pill/page_header/warning_banner)`。
- **规则**：所有展示走复合控件；禁止页面内 `style="...color:#xxx..."` 裸写（统一收口到 `ui.py` + 令牌）。
- **新增**：`state_banner`（loading/empty/error 三态）、`section_title`、`tag_chip`、`data_table`（统一 `column_config` 与斑马/对齐）。
- **审计交付**：逐页（12+ 页）输出"复用清单"，将裸 `st.markdown` 改为组件；此项纳入改造 PR 检查清单。

### 2.4 响应式 / 移动优先

Streamlit 非原生响应式，采用**约束内可行策略**：
- 全局 `style.css` 增加 `@media`：≤`--bp-md` 时 `.block-container` 内边距收紧、`st.columns` 退化为纵向堆叠、KPI 卡两列→单列、表格 `use_container_width`。
- 关键页（仪表盘/筛选/交易）做**窄屏专用重排**（隐藏次级列、折叠 Tab 为选择器）。
- 不套第三方 CSS 框架（遵守"纯 Python 前端"红线）；用 CSS 变量驱动断点。

### 2.5 可访问性（AA）

- 对比度：正文 `--text-body/#374151` on `#FFF` ≥ 4.5:1；小字 `#6B7280` 仅用于辅助标签。
- 焦点：`--focus` 焦点环应用到所有交互；`prefers-reduced-motion` 降级动画。
- 语义：`skip-link` 跳主内容；图标按钮加 `aria-label`；所有 `unsafe_allow_html` 内联 HTML 经统一净化封装（复用 `ui._escape`/bleach）。
- 键盘：Tab 顺序校验，避免纯 `on_click` 隐藏可达性。

### 2.6 前后端联动与状态规范

- **三态组件** `state_banner`：loading（骨架）/ empty（空数据引导）/ error（降级提示，不抛栈）。
- **示例数据角标**全局贯穿：Mock 模式下每页顶部强制显示，且 `source_footer` 标注"示例"。
- **联调开关**：`MOCK_MODE` 仅 dev 默认开；提供"联调自检页"（后台管理）展示各接口真实/降级状态。
- **health 门禁**：首页后端状态药丸区分"未就绪/降级/正常"，失败不阻断但明确提示。

### 2.7 部署交付

- 生产 `docker-compose.override.yml` / Secrets：`MOCK_MODE=0`、关闭 `runOnSave`、注入 `STREAMLIT_API_BASE`。
- 多阶段 `Dockerfile`：构建期装 `requirements-dev` 跑 lint/type/test，运行期仅 `requirements.txt`；streamlit 服务加 healthcheck。
- 文档：在《开发规范》§10 补充"前端构建/部署/环境变量"小节，明确 Mock 关闭与 Secrets 注入。

### 2.8 审美与合理性

- **视觉层次**：页头色带 → 区块标题 → 卡片 → 辅助文字，四级清晰；主操作（翠绿主按钮）唯一突出。
- **信息密度**：列表/表格行高、字距按 `--space-*` 对齐；仪表盘首屏"状态→榜单→学习"三段不溢出。
- **合理性**：动态"数据截至"（取后端 `as_of`，不再硬编码 2025-07-20）；角色切换与后端账户体系打通（P1-10b 后台管理）；免责声明全站统一常量。
- **一致性校验**：新增 `tests/test_frontend_tokens.py`：断言令牌值单向对齐、无游离色、涨跌语义唯一。

## 3. 验收标准（生产交付级 CheckList）

| 项 | 标准 | 验证方式 |
|----|------|----------|
| 配色唯一 | 涨跌语义全站唯一，与令牌一致 | `test_frontend_tokens` + 人工走查 |

| a11y | 对比度 AA、焦点环、skip-link | axe/手动 + 键盘走查 |
| 联调 | 三态组件齐备、Mock 角标贯穿 | 联调自检页 + 走查 |
| 部署 | 生产 `MOCK_MODE=0` + Secrets，无 runOnSave | compose override 评审 |
| 文档同步 | 原型§5/开发规范§10/CHANGELOG 已更新 | PR 检查清单 |
| 一致性 | 12+ 页复用复合控件，无裸内联样式 | 复用清单 + 走查 |
