## 1. 背景与动机

项目进入 Phase 1 中后期（整体进度过半，阶段评审 `REVIEW_20260730` 给出 Go），后端采集/评估/筛选/模拟交易主干已闭环、金融红线 E1–E14 无回退。但**前端经人工测试，整体未达"金融产品生产交付级"水平**，具体问题横跨八个维度：颜色、组件、样式、大小、部署、联动、审美、合理性。

经对 `feat/frontend-ui` 分支源码审计（`app/`、`app/components/`、`app/static/style.css`、`app/utils.py`、`app/api_client.py`、`docker-compose.yml`、`Dockerfile`），确认以下现状痛点（均有代码证据）：

1. **配色语义自相矛盾（最严重）**：`app/utils.py:pct_color()` 遵循 **A 股"红涨绿跌"**（`#E23B3B` 表示上涨），而 `app/static/style.css` 设计令牌与 `app/components/kpi_card.py` 采用 **"翠绿=正收益"**（`--brand #16A34A` 表示正）。同一"涨/跌"数值在系统中出现**两套相反配色**，违反金融产品"涨跌语义必须全局唯一"的合规底线。
2. **设计令牌未单一源落地**：`app/static/style.css` 已定义较完整的"翠绿专业风"令牌，但组件/页面中仍散落 **13 处裸 `#6B7280`**、以及 `#0A6B4A / #16A34A / #E23B3B / #FDE8E8` 等内联字面量；更出现 **`#fdeeee / #f0d39a / #8a5a00` 等令牌体系外的游离色**，导致主题换肤/品牌调整时内联色无法同步。
3. **无响应式 / 移动优先缺失**：`style.css` 仅做 `max-width:100%` 全局铺满，**无任何 `@media` 断点与栅格系统**；当前 `layout="wide"` 桌面优先，窄屏/移动端未适配（金融用户大量使用手机）。
4. **可访问性（a11y）不足**：缺少对比度校验（AA）、`focus` 焦点环、`skip-link`、键盘可达性声明；`st.markdown(unsafe_allow_html=True)` 内联 HTML 部分未统一净化路径。
5. **前后端联动未落地**：`MOCK_MODE` 默认 `"1"`，`api_client.is_mock()` 在 `health()` 失败时返回 `True`；全部 12+ 页仍走示例数据，阶段评审已指出"前端页面未与后端联调"。生产交付须明确联调计划与"示例数据"提示的合理性边界。
6. **部署交付口径不清**：`docker-compose.yml` 的 streamlit 服务 `MOCK_MODE` 默认开、`.streamlit/config.toml` 含 `runOnSave=true`（开发态）；生产须走 Docker Secrets 注入并关闭 Mock、关闭 runOnSave，且无前端构建/资源管线说明。
7. **组件复用与审美一致性待审计**：已建 `kpi_card / score_panel / ranking_table / brinson_chart / diagnosis_table / style_box` 等复合控件，但各页对统一控件的复用率、裸 `st.markdown` 内联样式的使用面需逐页盘点；视觉层次、间距尺度、字号阶梯、信息密度尚未形成可复核规范。
8. **文案/合理性过时**：硬编码"数据截至 2025-07-20"、免责声明贯穿性、角色切换（`st.session_state.role`）未与后端账户体系打通等。

> 上述 1/2/3/4/5/6 均属**前端表现层**，不触动后端 7 字段信封、错误码体系、数据库 Schema、接口契约与 E1–E14 金融算法口径——故定级 **C2**。

## 2. 变更内容

### 新增
- 设计令牌 v2：以 `app/static/style.css` 为**唯一权威源**，补充断点/间距尺度/字号阶梯/阴影层级/焦点环变量；Python 侧 `app/utils.py` 颜色常量与令牌值**单向对齐**（不再出现令牌外游离色）。
- 响应式栅格与移动优先策略（Streamlit 约束下的可行方案，见改造方案文档）。
- 可访问性基线（对比度 AA、focus ring、skip-link、reduced-motion、净化内联 HTML 的统一封装）。
- 前端联调与状态规范：loading / empty / error 三态、示例数据角标统一、联调开关与降级说明。
- 部署交付说明：生产 `MOCK_MODE=0`、Docker Secrets、关闭 `runOnSave`、静态资源/构建说明。

### 修改
- **配色语义统一决策**（关键子项）：在"翠绿=正收益（现行令牌）"与"红涨绿跌（A 股惯例）"二者中**明确择一并全局统一**。若选择红涨绿跌（推翻原型§5 设计意图），该子决策须**先更新《前端原型》+《开发规范》§10 设计令牌**，按 C3 子流程走（先改文档再实现）。
- 消除全部内联硬编码色值，改为引用令牌/CSS 变量。
- 统一 12+ 页对复合控件的复用，收敛裸 `st.markdown` 内联样式。
- 更新过时文案与免责声明贯穿逻辑。

### 删除
- 删除令牌体系外的游离色与重复内联字面量（以令牌替代，非删除功能）。
- 删除开发态 `runOnSave=true`（生产镜像中关闭）。
